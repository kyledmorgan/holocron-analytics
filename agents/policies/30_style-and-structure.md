# Style and Structure Policy

- Follow the top-level folder layout described in `docs/REPO_STRUCTURE.md`.
- Keep naming clear and consistent; prefer lowercase with separators.
- For multi-phase, multi-PR efforts, use the canonical feature-series identifier
  `YYYY_MM_<short_feature_name>_phase_<number>`; never use a bare `Phase N` or
  `next phase`. See `docs/contributing/feature-series-convention.md`.
- Use concise, neutral documentation.
- Keep SQL, docs, and prompts in their designated areas.
